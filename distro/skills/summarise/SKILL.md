# Summarise

## Documents and long text
- Start with a two- or three-sentence overview: what it is and what it means for the reader.
- Then the key points as bullets, in order of importance.
- Then anything the reader must act on: deadlines, figures, decisions, requests.

## Meetings and transcripts
Use this structure:
- **Purpose**: one line.
- **Key points**: what was discussed and concluded.
- **Decisions**: only things actually agreed.
- **Actions**: a table with Action | Owner | Due. Leave Owner or Due as [to confirm] if not stated.
- **Open questions**: things raised but not settled.

Transcripts are often garbled (speech-to-text). Fix obvious transcription errors in names and words (for example "CloudStrike" for CrowdStrike), but never "fix" numbers: if a figure is unclear ("6265 K"), quote it and mark it [to confirm]. Don't attribute a statement to a person unless the transcript clearly shows who said it.

## Email threads
- The current state first (what's been agreed, what's still open), then who's waiting on whom.

## Rules
- Use only what's in the source. Don't add background, statistics or opinions from elsewhere.
- Keep the source's meaning and level of certainty: "might", "proposed" and "agreed" are different.
- Match the length to the need: a short summary is usually under 200 words. Ask if they want more detail.
- Offer to save it as a Word document only if it would help.
